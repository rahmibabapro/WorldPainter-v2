# Startup profiling note (#491)

- Date: 2026-08-31
- Goal: reduce Windows cold-start with many custom brushes / overlays

## Findings (code)

- [`BitmapBrush(File)`](../../WorldPainter/WPGUI/src/main/java/org/pepsoft/worldpainter/brushes/BitmapBrush.java) already **defers pixel decode** until first strength sample (soft reference reload).
- Overlay images already **lazy-load** in [`WorldPainter.drawOverlays`](../../WorldPainter/WPGUI/src/main/java/org/pepsoft/worldpainter/WorldPainter.java) when `overlay.getImage() == null`.
- Remaining startup cost: scanning brush folders, decoding **palette `icon.png`**, and building dock UI for every brush group.

## Mitigation applied

- Defer `icon.png` decode until the brush group icon is first requested (`BrushGroup.getIcon()`).
- Index brush files without forcing ImageIO on every brush at startup (already true for brush bodies).

## How to re-measure

```powershell
# Launch with JFR (adjust paths)
$jfr = "$env:TEMP\wp-startup.jfr"
# Example with installed JDK:
# java -XX:StartFlightRecording=filename=$jfr,duration=30s -jar WorldPainter-v2.jar
```

Compare wall time from process start to main window ready before/after with ≥25 custom brushes in `%APPDATA%\WorldPainter [V2]\brushes`.
